
# Основные навыки
Вот некоторые вещи, которые я считаю основными для CTF, вызовов типа Hack the Box и веб-хакинга.

Навыки включают знание, как передавать файлы между компьютерами, взламывать пароли, получать удаленный доступ к машине, выполнять сканирование, анализировать HTTP-запросы и писать скрипты на bash или python.

Каждый навык связан с более подробным разделом в cheat-sheet, и некоторые даже содержат ссылки на практические примеры использования этих навыков на машинах или вызовах.

Начните с этого, если вы полный новичок!

## Удаленный доступ к компьютеру

### SSH

SSH означает «безопасный сокет», и является одним из самых основных способов получить удаленный доступ к другому компьютеру.

Удаленный доступ SSH контролируется ключами, используя криптографическую крипту открытых ключей.

Протокол SSH также обеспечивает многие другие инструменты и сервисы, такие как [[Linux Networking#Secure Copy|Secure Copy]] и порт forwarding.

**Базовая синтаксис**

```bash
$ ssh [user@]IP_ADDRESS
```

Часть `user@` является опциональной и указывает конкретного пользователя, с которым вы хотите соединиться. Обычно это `root`, но это может зависеть от ssh-конфигурации хоста.

#### SSH ключи

SSH ключи представляют собой пару открытых-приватных ключей. Это криптографическая схема с множеством применений, от шифрования до проверки идентичности.

Во время SSH ключи используются для идентификации в SSH-сервере. Сервер может хранить список **открытых ключей** (обычно в `~.ssh/authorized_keys`), который указывает, какие совместимые **приватные ключи** он принимает.

Каждый SSH-клиент (то есть компьютер, соединяющийся) имеет свой **приватный ключ**, который он представляет серверу. Если приватный ключ совпадает с известным открытым ключом, сервер принимает соединение.

Чтобы создать пару открытых-приватных ключей, используйте `ssh-keygen`. Это попросит вас добавить паролевую фразу в свой ключ, что рекомендуется для дополнительной безопасности:

```bash
$ ssh-keygen
Generating public/private rsa key pair.
Enter file in which to save the key (/home/user/.ssh/id_rsa):
Enter passphrase (empty for no passphrase):
Enter same passphrase again:
Your identification has been saved in /home/user/.ssh/id_rsa.
Your public key has been saved in /home/user/.ssh/id_rsa.pub.
...[SSH Fingerprint]...
```

Это создаст пару ключей и сохранит их в вашем каталоге `~/.ssh`. По умолчанию они будут называться `id_rsa` (ваш **приватный ключ**) и `id_rsa.pub` (ваш **открытый ключ**).

Вы можете изменить название этих ключей, указав флаг `-f`, который также позволяет указать место, где вы хотите их сохранить. Это полезно, если у вас много ключей:

```bash
$ ssh-keygen -f test
Generating public/private rsa key pair.
Enter passphrase (empty for no passphrase):
Enter same passphrase again:
Your identification has been saved in test.
Your public key has been saved in test.pub.
```

Чтобы соединиться с приватным ключом, используйте флаг `-i` (запомните, *i* для «идентичность»):

```bash
$ ssh -i /path/to/private/key [user@]IP_ADDRESS
```

Клиенты также хранят список «известных хостов», который указывает, какие открытые ключи они доверяют. Это предотвращает злонамеренных актерах, имитирующих сервер, с которым вы пытаетесь соединиться, например, в атаке man-in-the-middle (MITM). Если вы пытаетесь соединиться с хостом, чей открытый ключ изменился с момента последнего соединения, будет показано предупреждение.

**Никогда не раскрывайте свой приватный ключ**. Это позволит кому-то имитировать вас и потенциально получить доступ к вашему серверу.

##### Использование SSH ключей для доступа

Если вы можете писать в файл `.ssh/authorized_keys` пользователя, вы можете создать свой открытый ключ и затем подключиться через SSH с использованием приватного ключа как файла идентификации.

Эта ситуация может возникнуть, когда:
- вы можете использовать эксплойт для записи в файл, но не можете выполнять произвольный код
- вы можете выполнять произвольный код, но только одно команду за раз в ограниченном сетевом окне, и вы хотите [[Linux Shells#Upgrading a Shell|обновить свой сетевой интерфейс]]

- ваш сетевой интерфейс может быть закрыт, и вы хотите получить постоянный доступ к машине (то есть повторяемый доступ)

Практический пример можно найти в [[15 - Shell as www-data#SSH Persistence]]

## Обмен файлами между компьютерами

Есть много ситуаций, когда вы можете захотеть передать файл на удаленный хост. Самый частый пример — когда загружаете скрипт поиска имен на машину, на которую вы получили футуху.

Вы также можете хотеть скачивать файл с удаленного хоста — например, когда эксфилтруют данные или скачивают бинарный файл, чтобы увидеть, как он работает.

### Python веб-сервер

Это один из самых простых способов передачи файлов. Он включает запуск базового HTTP-сервера на вашем компьютере и использование этого для предоставления файлов удаленному компьютеру.

Если у вас еще нет этого, вам нужно [установить python](https://www.python.org/downloads/). Вы можете проверить, есть ли он, выполнив `which python` или `which python3` в терминале. Если оба возвращают пустоту, вы не установили его правильно.

Когда у вас уже есть Python, запустите сервер:

```bash
$ python3 -m http.server
```

По умолчанию этот слушает порт 8000. Вы можете изменить порт, указав неиспользуемый номер порта после команды:

```bash
$ python3 -m http.server [PORT]
```

Если вы хотите слушать привилегированный порт (<1000), вам нужно запустить с привилегиями root. Запуск на порту 80 или 443 является распространенным случаем использования, так как это стандартные порты для HTTP и HTTPS.

```bash
$ python3 -m http.server [PORT]
```
