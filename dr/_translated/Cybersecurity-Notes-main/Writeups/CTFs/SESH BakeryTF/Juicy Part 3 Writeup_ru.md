Мы также можем использовать третью опцию для «создания» рецепта с помощью строки, сохранённой в базе данных. Это особенно интересно — введение случайной строки приводит нас к странице `get-recipe.php`, но на этот раз с параметром `string_id`. Введение `1` даёт зашифрованный рецепт mayonnaise.

Давайте попробуем узнать больше о том, как работает приложение. Интересно то, что при чтении файла рецепта необходимо указать `.txt` — это указывает на то, что мы можем напрямую обращаться к файловой системе. Можем ли мы получить LFI?

Оператор `..` позволяет перейти вверх по директории, вероятно, из директории, где хранятся файлы рецептов `.txt`, в основную директорию, где хранится код.

Теперь мы можем произвольно читать код веб-приложения!

![[Pasted image 20210511212512.png]]

Мы также могли бы использовать это для поиска конфиденциальных файлов — возможно, креды базы данных или SSH-ключи — но я знаю, что эта задача не включает удалённый доступ к базе данных или веб-серверу, поэтому не буду углубляться в это.

`create-recipe.php` показывает, что мы можем вставлять данные в базу данных:

![[Pasted image 20210511212607.png]]

Вот ключевой код:

```php
$recipe_string = $_GET["recipe_recipe"];

//проверка, что они отправляют класс SecretRecipe
if(strpos($recipe_string, 'O:12:"SecretRecipe"') !== false) {
    //вставка в базу recipe_strings
    error_log("Inserting");

    Database::initialize();

    $stmt = Database::$conn->prepare("INSERT INTO recipe_strings (recipe_recipe) VALUES (?)");

    //выполнение запроса с отправленной строкой

    $stmt->bind_param("s", $recipe_string);

    $stmt->execute();

    //закрытие запроса
    $stmt->close();

    //получение ID последнего элемента
    $id = Database::$conn->insert_id;

    echo("Спасибо за отправку! Ваш ID: ". $id);
}
```

Похоже, он ожидает сериализованный объект класса `SecretRecipe`, так как проверяет, что наша строка содержит `O:12:"SecretRecipe"`. Это указывает на возможность десериализации позже — возможно, в файле `get-recipe.php`?

Если мы передадим программе `string_id`, мы можем получить сериализованную строку из базы данных:

![[Pasted image 20210511212810.png]]

Крайне важно, что затем это десериализуется (через вызов `unserialize()`), и функция `__wakeup()` затем читает рецепт из базы данных по его ID:

```php
public function __wakeup() {
    //загрузка из БД после десериализации
    error_log("Woken up - getting from DB");

    $this->get_from_db();
}
```

Это указывает на то, что мы можем создать сериализованный объект `SecretRecipe`, который получает зашифрованный рецепт — но как мы можем использовать это?

Ну, есть `if`-строка, которая проверяет значение переменной `$encrypted` объекта — это определяет, является ли рецепт хешированным или нет:

![[Pasted image 20210511213257.png]]

Когда мы создаём сериализованный PHP-объект, мы имеем полный контроль над его переменными — поэтому можем установить собственную переменную `$encrypted` объекта на `False`, так:

```php
O:12:"SecretRecipe":4:{s:9:"encrypted";b:0;s:5:"title";s:4:"Test";s:8:"contents";s:4:"Test";s:2:"id";i:1;}
```

Это сериализованный PHP-объект — строка `O:12:"SecretRecipe"` указывает на класс, а строки в фигурных скобках указывают на переменные класса. Важные переменные — `"id";i:1`, где целое число `1` (ID рецепта, который мы хотим получить) и `"encrypted";b:0`, где указано, что мы хотим установить `$encrypted` на `false`.

Если это не имеет смысла, вы можете узнать больше о десериализации с простым примером из моего [[Deserialisation Demo|демо на тему]].

Давайте отправим это на страницу `create-recipe.php`, посетив `http://localhost:5000/create-recipe.php?recipe_recipe=O:12:%22SecretRecipe%22:4:{s:9:%22encrypted%22;b:0;s:5:%22title%22;s:4:%22Test%22;s:8:%22contents%22;s:4:%22Test%22;s:2:%22id%22;i:1;}`:
