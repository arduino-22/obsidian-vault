## Получение IP-адреса

Используйте этот команду, чтобы увидеть свой IP-адрес. `ifconfig` сам по себе выведет список всех интерфейсов, или вы можете указать конкретный интерфейс.

```bash
ifconfig [interface]
```

## SSH

### Генерация ключевой пары

Сгенерируйте публичный и частный ключ с помощью следующей команды. По умолчанию ключи сохраняются в директории `~/.ssh`.

```bash
$ ssh-keygen
```

Вы также можете указать имя ключа с флагом `-f`. По умолчанию частный ключ называется `id_rsa`, а публичный — `id_rsa.pub`.

```bash
$ ssh-keygen -f key_name
```

### Сквозное копирование
```bash
$ scp [OPTION] [[user@]SRC_HOST:]file1 [[user@]DEST_HOST:]file2
```

## Проверка соединения

Как проверить, можно ли заставить компьютер отправлять сообщения?

### Netcat

Слушатель Netcat полезен по многим причинам, включая захват оболочек. Но он также подходит для тестирования одиночного соединения, например HTTP-запроса.

Базовая синтаксис для слушателя Netcat:

```bash
$ nc -lp [PORT]
```

Это примет входящее соединение и соберет данные о браузере запросчика.

Чтобы начать на привилегированном порту, например 80 или 443, необходимо запустить с правами root:

```bash
$ sudo nc -lnvp 80
```

Для дополнительной информации используйте флаг `-v` для визуального режима. Используйте флаг `-n`, чтобы не выполнять поиск DNS на входящих соединениях. Это стандартная команда Netcat, которую я использую:

```bash
$ nc -lnvp [PORT]
```

Netcat может принимать любые данные, отправленные через TCP или UDP (практически любой веб-трафик, кроме запросов `ping`).

По умолчанию Netcat закрывается после одного соединения. Чтобы слушатель остался открытым после соединения, используйте флаг `-k`.

### Python веб-сервер

Python веб-сервер лучше, чем Netcat, если вы хотите отправлять несколько запросов, так как по умолчанию остается открытым после соединения. Однако Python веб-сервер по умолчанию не собирает много информации, например строки User Agent.

На хосте запустите веб-сервер:

```bash
$ python3 -m http.server [PORT]
```

(*Примечание:* По умолчанию слушает порт 8000. Больше информации см. в [[Fundamental Skills#Filesharing Between Computers]])

Затем установите соединение с вашим компьютером, используя любой доступный метод:
- Curl: `$ curl http://[IP]:[PORT]`
- Wget: `$ wget http://[IP]:[PORT]`
- Netcat: `$ nc [IP]:[PORT]`
- Curl.exe (Windows 10): `curl.exe --url http://[IP]:[PORT]`
- Powershell: `powershell -command "Invoke-WebRequest -Uri http://[IP]:[PORT]"`

Смотрите следующую [Stack Overflow статью](https://serverfault.com/questions/483754/is-there-a-built-in-command-line-tool-under-windows-like-wget-curl) для дополнительных вариантов на Windows.

### Ping

Для запросов, не относящихся к TCP/UDP, запустите tcpdump и отправьте ping.

На хосте запустите слушатель ICMP (ping) запросов:

```bash
┌──(mac㉿kali)-[~]
└─$ sudo tcpdump -i [INTERFACE] -n icmp
[sudo] password for mac: 
tcpdump: verbose output suppressed, use -v[v]... for full protocol decode
listening on tun0, link-type RAW (Raw IP), snapshot length 262144 bytes
```

На целевом компьютере выполните ping с помощью:
- `ping -c 1 [IP]` (Linux)
- `ping -n 1 [IP]` (Windows)

Один ping достаточен, если у вас нет интерактивной удаленной выполнения кода (то есть можно отправить команду, но не нажать `Ctrl + C` для остановки). В противном случае компьютер будет продолжать pingать вечно.

## PHP веб-серверы

Подобно Python веб-серверу, этот запускает сервер локально и быстро, и дает выводы. Однако он более полезен для предоставления файлов на PHP, чем для передачи файлов между компьютерами.

Если вы хотите тестировать PHP-скрипт локально, можно запустить PHP веб-сервер в директории предоставления файлов так:

```bash
$ php -S localhost:[PORT]
```

Как и с Python, необходимо иметь права root для запуска на привилегированном порту (<1000).

Затем можно получить доступ к PHP-файлам с помощью Curl или в браузере. Например, тестирование веб-шелла:

```bash
$ curl http://localhost:**[PORT]/cmdphp.php?cmd=id
```

PHP веб-серверы также полезны для тестирования веб-приложений на удаленном компьютере. Если вы настроили [[Linux Networking#With SSH|SSH туннель]] к удаленному серверу, можно запустить PHP-сервер для тестирования и просмотра вывода. Это помогает отлаживать сервер удаленно.

Практический пример этого можно найти в [[20 - Shell as roy#Testing the Web App]]

## Туннелирование

Используйте туннелирование для доступа к удаленному порту через локальный порт.

Например, если веб-сервер работает локально на удаленном компьютере (он не экспонирован в интернете), если этот сервер работает на порту 9999, его можно получить через `http://localhost:9999` на удаленном компьютере.

Если у нас есть способ туннелирования к этому компьютеру, мы можем настроить реле от нашего компьютера к удаленному. Например, мы можем указать наш порт 8000 на удаленный порт 9999 сервера. Если IP удаленного сервера — `192.0.0.2`, туннель будет выглядеть так:
- Мы отправляем запрос на `http://localhost:8000` на локальном компьютере
- Этот запрос передается через туннель на `http://192.0.0.2:9999`

Эта настройка позволяет, например, получить доступ к веб-сайту в браузере, с которым ранее можно было взаимодействовать только через командную строку.

### С помощью SSH

Если у нас есть SSH-доступ к этому компьютеру, мы можем использовать SSH туннелирование для достижения цели:

```bash
$ ssh -L 8000:localhost:9999 [USER@]192.0.0.2 [-i /path/to/private/key]
```

Это предполагает одинаковые адреса, как выше. Команда попросит вас войти или использовать приложенный частный ключ. После завершения SSH-соединения откроется SSH терминал, и туннель будет настроен.

Затем можно «пройти» на локальный веб-сервер удаленного хоста, посетив свой localhost:

```bash
$ curl localhost:8000
```

Хороший руководитель по этому процессу можно найти на [Linux Hint](https://linuxhint.com/ssh-port-forwarding-linux/), где приведены инструкции по настройке SSH.
